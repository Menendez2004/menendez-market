# Create order from cart — API handoff

## Summary

Checkout can now turn the user's cart into an order. The frontend submits
the cart lines and the shipping address to `POST /api/v1/orders`, gets back
an order in `pending_payment` status, and shows the confirmation page by
reading it with `GET /api/v1/orders/{orderId}`.

## What the receiver must do

1. Add `createOrder(input)` and `getOrder(orderId)` to the API client in
   `src/api/orders.ts`, using the types in **Receiver notes**.
2. On the checkout page, call `createOrder` when the user presses
   "Place order"; disable the button while the request is in flight.
3. Send one `Idempotency-Key` per click on "Place order" and reuse it for
   automatic retries of that same click.
4. On `201`, navigate to `/orders/{id}/confirmation`, which loads the order
   with `getOrder`.
5. Handle every error in the **Errors** tables as described in
   "Receiver must".

**Out of scope:** payment. The order stays in `pending_payment`; the
payment handoff is separate.

## Conventions

| Item | Value |
|---|---|
| Base URL | `{API_BASE_URL}` — `VITE_API_BASE_URL` in each environment |
| Auth | `Authorization: Bearer <access_token>` from the auth store |
| Content type | `application/json; charset=utf-8` |
| Field casing | camelCase |
| Dates | ISO 8601 UTC strings, e.g. `2026-10-09T14:05:00Z` |
| Money | integer minor units (cents) + ISO 4217 `currency` |
| IDs | UUID v4 strings |
| Pagination | None. |

**Error envelope** (every non-2xx response, from `src/common/http-exception.filter.ts`):

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "items[0].quantity must not be greater than 99",
    "details": [{ "field": "items[0].quantity", "issue": "max" }]
  }
}
```

`code` is stable and safe to branch on. `message` is for logs, not for the
UI. `details` is present only for `VALIDATION_ERROR`.

## Endpoint 1 — POST /api/v1/orders

### Purpose

Creates an order from the cart lines the user is checking out, reserving
stock. Used by the checkout page's "Place order" button.

### Request

| Item | Value |
|---|---|
| Method | `POST` |
| Path | `/api/v1/orders` |
| Auth | required, any signed-in customer |
| Idempotent | yes — same `Idempotency-Key` within 24 h returns the first response |
| Rate limit | 10 requests / minute / user |

#### Path parameters

None.

#### Query parameters

None.

#### Headers

| Name | Required | Value |
|---|---|---|
| `Idempotency-Key` | yes | UUID v4 generated by the client, one per "Place order" click |

#### Body

| Field | Type | Required | Rules / description |
|---|---|---|---|
| `items` | array | yes | 1–50 lines |
| `items[].productId` | string (uuid) | yes | product to buy |
| `items[].quantity` | integer | yes | 1–99 |
| `shippingAddress` | object | yes | where to ship |
| `shippingAddress.line1` | string | yes | 1–120 chars |
| `shippingAddress.line2` | string \| null | no | 0–120 chars, default `null` |
| `shippingAddress.city` | string | yes | 1–80 chars |
| `shippingAddress.postalCode` | string | yes | 3–12 chars |
| `shippingAddress.country` | string | yes | ISO 3166-1 alpha-2, e.g. `MX` |
| `notes` | string | no | 0–500 chars |

```json
{
  "items": [
    { "productId": "3f6c1b2e-8a51-4c3e-9a7e-2b1d5f0c9e11", "quantity": 2 }
  ],
  "shippingAddress": {
    "line1": "Av. Ejemplo 123",
    "line2": null,
    "city": "Ciudad de México",
    "postalCode": "01000",
    "country": "MX"
  },
  "notes": "Leave at the front desk"
}
```

### Responses

#### Success

**`201 Created`** — the order was created. Header `Location: /api/v1/orders/{id}`.

| Field | Type | Nullable | Description |
|---|---|---|---|
| `id` | string (uuid) | no | order id |
| `status` | enum | no | always `pending_payment` on creation |
| `items[].productId` | string (uuid) | no | as sent |
| `items[].name` | string | no | product name at order time |
| `items[].quantity` | integer | no | as sent |
| `items[].unitPrice` | integer | no | cents |
| `total` | integer | no | cents, items + shipping |
| `currency` | string | no | ISO 4217 |
| `createdAt` | string (datetime) | no | ISO 8601 UTC |

```json
{
  "id": "9b0e7d4a-1c2f-4e8b-b3a6-5d7f8e9a0b1c",
  "status": "pending_payment",
  "items": [
    {
      "productId": "3f6c1b2e-8a51-4c3e-9a7e-2b1d5f0c9e11",
      "name": "Example product",
      "quantity": 2,
      "unitPrice": 24900
    }
  ],
  "total": 54800,
  "currency": "MXN",
  "createdAt": "2026-10-09T14:05:00Z"
}
```

#### Errors

| Status | `code` | When | Receiver must |
|---|---|---|---|
| 400 | `VALIDATION_ERROR` | body breaks a rule in the table | show each `details[].issue` next to its field; keep the form |
| 401 | `UNAUTHENTICATED` | token missing or expired | refresh the token once and retry with the same `Idempotency-Key`; if it fails again, go to login and keep the cart |
| 404 | `PRODUCT_NOT_FOUND` | a `productId` does not exist | remove that line from the cart and show "A product is no longer available" |
| 409 | `OUT_OF_STOCK` | not enough stock for a line; `details[].field` names it | mark that line out of stock and ask the user to adjust it |
| 422 | `IDEMPOTENCY_KEY_REUSED` | same key with a different body | generate a new key and resubmit |
| 429 | `RATE_LIMITED` | over 10 requests / minute | show "Too many attempts, wait a minute" and re-enable the button after 60 s |

### Behavior and side effects

- Creates the order and its lines in one transaction and reserves stock
  for 30 minutes; the reservation is released if payment does not start.
- Clears nothing on the client side: the frontend clears the cart only
  after `201`.
- Emits `order.created` (internal event; nothing for the frontend to do).

### Receiver notes

Types for `src/api/orders.ts`:

```ts
export interface CreateOrderInput {
  items: { productId: string; quantity: number }[];
  shippingAddress: {
    line1: string; line2?: string | null; city: string;
    postalCode: string; country: string;
  };
  notes?: string;
}
export type OrderStatus = "pending_payment";
export interface Order {
  id: string; status: OrderStatus;
  items: { productId: string; name: string; quantity: number; unitPrice: number }[];
  total: number; currency: string; createdAt: string;
}
```

Format money with `Intl.NumberFormat` using `currency` and dividing by 100.

### Acceptance criteria

- [ ] AC-1.1 Given a valid cart, when the user presses "Place order", one `POST /api/v1/orders` is sent with an `Idempotency-Key` header and the button is disabled until it resolves.
- [ ] AC-1.2 On `201`, the cart is cleared and the user lands on `/orders/{id}/confirmation`.
- [ ] AC-1.3 On `400`, each `details[].issue` is shown next to its field and the form keeps the user's input.
- [ ] AC-1.4 On `409 OUT_OF_STOCK`, the affected line is marked out of stock and no navigation happens.
- [ ] AC-1.5 On `401`, the client refreshes the token once and retries with the same `Idempotency-Key`.

## Endpoint 2 — GET /api/v1/orders/{orderId}

### Purpose

Returns one order of the signed-in user. Used by the confirmation page.

### Request

| Item | Value |
|---|---|
| Method | `GET` |
| Path | `/api/v1/orders/{orderId}` |
| Auth | required; only the order's owner |
| Idempotent | yes (read only) |
| Rate limit | None. |

#### Path parameters

| Name | Type | Description |
|---|---|---|
| `orderId` | string (uuid) | id returned by `POST /api/v1/orders` |

#### Query parameters

None.

#### Headers

None.

#### Body

No body.

### Responses

#### Success

**`200 OK`** — same `Order` shape as the `201` of Endpoint 1.

#### Errors

| Status | `code` | When | Receiver must |
|---|---|---|---|
| 401 | `UNAUTHENTICATED` | token missing or expired | same handling as Endpoint 1 |
| 404 | `ORDER_NOT_FOUND` | id does not exist or belongs to another user | show the "Order not found" page with a link to `/orders` |

### Behavior and side effects

None — read only.

### Receiver notes

Load it in the confirmation route loader; show a skeleton while loading.
Do not poll: the status does not change until payment exists.

### Acceptance criteria

- [ ] AC-2.1 The confirmation page shows each line's name, quantity and formatted price, and the formatted total.
- [ ] AC-2.2 On `404`, the "Order not found" page is shown.
